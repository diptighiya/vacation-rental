Notes

Issues #19 (add), #21 (details, hours, availability), #22 (description, photos, amenities)
  1. 1One form, two routes/new says "Add listing" and "Create listing". /:id/edit pre-fills the fields and says "Edit listing" and "Save changes". Saving an edit sends the listing back to admin review.
  2. 2BasicsTitle ≥ 8 characters. Description ≥ 30 characters, with a live character count. Price > $0 and ≤ $10,000. Max guests 1 to 16. Errors show inline under each field, using the same rules as the API contract.
  3. 3AddressZIP is 5 digits. The server geocodes the address to lat/lng, and a changed address is re-geocoded (#21).
  4. 4AmenitiesChosen from the predefined list (the amenities table), shown as toggle chips.
  5. 5PhotosDrag and drop or pick files, JPG/PNG only, up to 10. The first photo is the cover, and × deletes one. Reordering to pick a new cover is proposed in the contract (PUT …/photos/order). At least one photo is required.
  6. 6AvailabilityOne or more date ranges, and dates outside them are blocked from search. House hours are set with the check-in and check-out time pickers.
  7. 7SubmitValidates the whole form, then saves and returns to My listings with the toast "Listing saved — pending admin approval". Cancel goes back without saving.
Server errors come back as { error: { code, message, fields } }. Field messages go under their inputs, and anything else shows in a toast.
